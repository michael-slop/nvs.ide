nvs.ide LazyVim with training wheels, for people leaving VS Code

nvs.ide is the middle ground between VS Code and Neovim. Underneath it's stock Neovim running the full LazyVim setup. On top it adds the hand-holding VS Code users expect: familiar shortcuts that fade out over four stages, a coach that shows the Vim way, Ask for "how do I…" questions, built-in lessons, IntelliSense-style completion, and optional local AI through Ollama. Click into the editor below and try it. F1 opens Ask.

    Enter run · Esc close · Ctrl+J/K move

    Runs today The Neovim half already works

    The runtime/ folder in the repo is a working editor now. It's LazyVim plus the nvs.ide layer (the four stages, the coach, Ask, the lessons and local AI), and it runs in Neovide as a separate app next to your own config. The window in this preview is the design for the native shell that comes next.

    Try it

    scripts\try.ps1 links runtime/ as the nvs-ide app and starts Neovide with it. Your normal nvim config isn't touched.

    Tested

    A sandboxed LazyVim install passes 24 checks: commands, stage keymaps and restoring LazyVim's own, saved state, the lessons and their ✓ checks, and Ask's answers. Ghost text loads when local AI is on.

    Not yet

    The native window (Phase 1), the Settings screen and the Plugins view exist only in this preview. Ollama answers are untested against a live model.

    Ask Type a question, get the Vim way

    Press F1 or Space ? and ask in plain words: "delete a line", "split the screen", "how do I exit vim". Ask matches the question against written answers for the common tasks. Each answer gives the Vim keys, the VS Code keys you already know, and a Try it button. Nothing is generated and nothing leaves your machine.

    When nothing matches and Local AI is on, the question goes to your Ollama model along with the closest written answers, so the model stays grounded. If it suggests a : command, a Run button asks before running it. The preview and the editor read the same answers file, runtime/kb/ask.json.

    Completion IntelliSense-style suggestions, plus local AI

    The menu

    blink.cmp (LazyVim's completion engine) shows suggestions from the language server, snippets and open files as you type, with documentation beside them. Enter accepts, Ctrl+Space opens it by hand. Try typing vim.no in the editor above.

    Ghost text

    With Local AI on, minuet-ai.nvim asks a small Ollama model for longer grey suggestions, like Copilot on your own hardware. Alt+A accepts. In the preview, turn on Settings > Local AI, then type vim.notify(.

    Your models, your network

    The default address is http://localhost:11434. If Ollama runs on another machine, forward that port over SSH and leave the address alone. :NvsOllama status lists the models it can see.

    Lessons A built-in tutorial

    :NvsTutor opens nine short lessons written for VS Code users: moving, modes, deleting, changing, copying, search and save, the leader key, code navigation and stages. It uses Neovim's own tutor engine, so exercise lines show a red mark until you get them right, then turn green. :Tutor is still there for the full Vim course.

    The ramp Four stages from VS Code to Neovim

    The welcome screen asks once where you're coming from and picks a stage. Change it later in Learn, in Settings > Transition, or with :NvsStage. Stages only decide which keys nvs.ide handles before LazyVim sees them. Moving between them loses nothing, and LazyVim's own keys come back at Stage 4.

    Vim everywhere Not just the text area

    Every list moves like Vim

    Explorer, search results, git changes, plugins and the palette use j k gg G. l or Enter opens, h collapses, / filters.

    Panes are windows

    Ctrl+H/J/K/L (LazyVim's keys) or Ctrl+W h/j/l move between sidebar, editor and panel.

    Leader menu

    Space in Normal mode opens which-key: files, git, debug, plugins, settings, and ? for Ask.

    Settings speak Vim

    Every setting shows the Lua or command it maps to. Search by Vim name (rnu), and :set rnu! flips the same checkbox.

    Plugins The whole of LazyVim, pre-installed

    nvs.ide ships the full LazyVim set: snacks.nvim (finder, explorer, terminal), blink.cmp, which-key, gitsigns, flash, trouble, conform, nvim-lint, grug-far, mason, bufferline and more. It also turns on the harpoon and mini.surround extras. Telescope is one click away as an extra; snacks' picker does the same jobs by default. The Plugins view adds tabs for Extras (the same list as :LazyExtras) and Browse. Searching for a VS Code extension you miss finds its Neovim equivalent.

    Architecture Three processes, one optional

    nvs.ide shell (Phase 1)

    Rust, native window, GPU-rendered, forked from Neovide. It draws the chrome, Settings, Plugins, Ask and the coach. Neovim draws only the text.

    msgpack-RPC over stdio
    JSON-RPC, started on demand

    nvim --embed + runtime/

    Stock Neovim running LazyVim and the nvs.ide layer (working now).

    • lua/nvs: stages, coach, ask, ollama, state
    • kb/ask.json, tutor/nvs-ide.tutor
    providers proxied
    as a virtual LSP server

    extension host (optional)

    Node process with a subset of the vscode API, for Open VSX extensions.

    Plan Build order

    1. Design and runtime. This preview, and the working LazyVim-based runtime in the repo.
    2. Shell MVP. Fork Neovide into shell/. Workbench layout, native cmdline, popup menu and messages.
    3. Panels. Problems, Outline, Search, Git, Terminal and Debug fed by the bridge. Ask and the coach move into the window.
    4. Settings and Plugins screens. The settings schema writing Lua, VS Code import, and the lazy.nvim / LazyExtras front end.
    5. Extension host. Open VSX, Tier 1 conversion, then Tier 2 providers.
    6. Packaging. Windows first (scoop and an msi).
